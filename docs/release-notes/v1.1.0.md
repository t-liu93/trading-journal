# v1.1.0 · Option entry and journal consistency

> **English** · [中文](v1.1.0.zh.md)

M-OPT-01 is complete and accepted after the five-step owner walkthrough. This release improves option discovery, contextual trade entry, dates and notes without adding a database migration.

## Changes

- Instrument lists and pickers hide expired options by default, retain contracts expiring today, and provide an expired-history switch and pagination. Historical selected values continue to resolve by ID.
- With a stock-resolving Primary Instrument, Trade candidates contain only that exact stock and its options. Changing the primary clears old search terms and incompatible option selections while preserving other entered values.
- Inline option creation inherits and locks the underlying, currency and exchange in First Trade, subsequent Trade entry and PMCC Meta. Locked instruments display their names instead of cached UUID labels.
- Opening dates follow the earliest active fill after creation or archival. Closing dates default to the latest active fill; invalid date ordering is rejected atomically. Frozen P&L, archival and closed-position Trade locks remain enforced.
- Position and Trade timestamps returned without an offset are interpreted as UTC before browser-local display. A local 10:00 entry displays as 10:00 after saving, including winter and summer offsets.
- Notes appear directly below their own Trade, preserve newlines, wrap long text and render HTML-like text literally. Save, clear, cancel and Ctrl/Command+Enter work in that row.
- Trade-entry labels, help and validation use a consistent layout, preserve multi-leg input and retain Position/first-Trade retry recovery.
- Frontend behavior tests now run in CI alongside the existing backend, code-generation and build checks.

## API compatibility

`GET /api/instruments` adds `offset`, `include_expired`, `option_underlying_id` and `related_underlying_id`. The response remains an array. The API defaults to `include_expired=true` for older clients; product screens explicitly request `false`.

`option_underlying_id` restricts option rows only. `related_underlying_id` narrows results to the exact stock and its options. All filters run before ordering and pagination. ID lookup and instrument get-or-create behavior remain available for historical records.

## Upgrade notes

No new Alembic migration or historical data backfill is included. Keep the existing database and use the normal migrate-before-app deployment flow after taking a consistent backup. This release does not rewrite stored times or repair historical closed records automatically.

The versioned image is `ghcr.io/t-liu93/trading-journal:1.1.0`; the existing release workflow publishes `linux/amd64` and `linux/arm64`, plus the `1.1`, `1` and `latest` aliases. Publishing an image does not replace a running deployment. See the [current deployment guide](../../README.md#deployment) and [isolated walkthrough](../walkthrough.md).

The initial milestone and R1 search/filter correction passed independent review. Not every error/API branch was manually repeated; detailed boundaries are in the [milestone acceptance record](../plan/milestone-option-entry.md#52-completion-criteria).

## Remaining scope

Strategy-derived parameters, multi-leg templates, audited correction of closed records, atomic Position/first-Trade server creation and automated release gating remain deferred. SQLite is supported; PostgreSQL equivalence is unverified. Live pricing, imports and currency conversion are outside this release.
