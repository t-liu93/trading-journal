# v1.2.0 · 通过 MCP 进行 Agent 自然语言交易录入

> [English](v1.2.0.md) · **中文**

M-MCP-01 已使用真实 Codex 和 Nous Research Hermes 客户端完成九步本机用户走查并获接受。Agent 可以查询日志、准备不可变录入预览，用户在对话中明确确认后提交。

## 变更

- Streamable HTTP MCP 在现有应用和数据库内运行，路径精确为 `/api/mcp`。六个查询工具覆盖上下文、账户、品种、Position 和 Trade；`prepare_entry` 与 `commit_entry` 提供有限录入流程。
- Settings → MCP Credentials 创建独立、具名、可撤销的 `read` 与 `entry` 凭证。密钥仅显示一次，只保存摘要与显示前缀，默认有效期 90 天。每次请求均执行服务端所有权及权限检查。
- 录入支持新仓位及首批成交、已有未平仓仓位追加单腿／多腿成交，以及随录入创建缺少品种。准备阶段仅保存草稿，包含合约规格、默认值、费用、权威 Decimal 现金流和时间解释。
- 待提交预览 24 小时过期。用户确认后，品种、仓位、全部成交及保存结果在同一事务中提交；失败整批回滚，重复／并发提交及响应丢失后的重试返回原结果，不重复记账。准备沿用原 `request_id`，提交沿用原 `draft_id`。
- `JOURNAL_TIMEZONE` 显式设置服务器录入时区，默认 `UTC`；支持每腿 IANA 时区及明确偏移，夏令时歧义／不存在时间需提供偏移。数据库继续存 UTC，网站按浏览器本地时间显示。
- 同一入口支持本机 loopback 与 HTTPS 反代访问。远程访问配置准确的允许 Host／Origin，并保留 MCP 路径、Bearer 授权和协议头。

## 兼容性与边界

现有网站的仓位／首批成交创建和失败恢复保持不变，MCP 原子创建不迁移网站流程。Trade 归档、已平仓写锁、冻结盈亏、只追加计划、数值精度与币种分离均保留。

本版本不加入截图识别、应用内模型 API／聊天界面、券商导入、平仓／重开／归档／纠错 MCP 工具或其他管理写入。支持 SQLite，PostgreSQL 等价性仍未验证。

## 升级说明

升级前制作一致数据库备份，并单独验证恢复。沿用 Compose 的先迁移后启动流程，新增三条 Alembic revision，从 `0003` 升至 `0006`：

| Revision | 新增内容 |
|---|---|
| `0004` | 独立 MCP 凭证记录 |
| `0005` | 品种创建的共享写入协调 |
| `0006` | 不可变录入草稿及提交来源／结果 |

不重写历史交易数据，也不回填历史时间戳。升级后回滚部署尚未验证；保留兼容的升级前备份与镜像，不假定旧镜像可以直接使用升级后的 schema。

版本镜像为 `ghcr.io/t-liu93/trading-journal:1.2.0`；标签 workflow 构建 `linux/amd64`、`linux/arm64`，并发布 `1.2`、`1` 和 `latest` 别名。发布不替换运行中的部署。配置见[部署说明](../../docs/README_zh.md#部署)及 [MCP 设置／走查](../walkthrough.zh.md#mcp-客户端设置与走查)。在目标服务创建新凭证；走查凭证已撤销，临时数据库已删除。

## 验证与验收

实现检查通过：Ruff、严格 mypy、472 项后端测试、59 项前端测试、前端生产构建及 OpenAPI 类型精确新鲜度。候选镜像通过全新／升级迁移、health／登录／SPA／重启及 HTTP MCP 检查。回归覆盖事务回滚、重复／并发提交、响应丢失重试、凭证／所有权／已平仓检查、Decimal 精度及时区边界。

T1–T6 和阶段 B 集成候选独立评审通过。真实 Codex CLI 0.166.0、Hermes CLI 0.22.5 完成预览／确认／提交后，用户确认本机网页数据与时间结果。走查还验证缺少期权及两腿录入、更早成交前移开仓时间、默认／IANA／偏移等价、重试返回一致、撤销凭证拒绝及 read 权限直接写调用被拒绝。临时凭证及运行资源已全部清理，原开发数据库与现有部署保留。

本机 HTTPS 代理及 Host／Origin 自动检查通过；真实第二台机器的远程用户走查仍未运行，不用 SDK／HTTP 测试替代实际客户端验收。用户延后 Settings／MCP 导航问题（`MCP-NAV`）。最终文档整理不构成新的应用评审，详细范围与验收见[里程碑](../plan/milestone-mcp-entry.zh.md#52-状态与完成条件)。
