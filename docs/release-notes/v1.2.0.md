# v1.2.0 · Agent-driven trade entry through MCP

> **English** · [中文](v1.2.0.zh.md)

M-MCP-01 is accepted after the nine-step local owner walkthrough with actual Codex and Nous Research Hermes clients. Agents can query the journal, prepare an immutable entry preview and commit it after explicit confirmation in the conversation.

## Changes

- Streamable HTTP MCP runs at exactly `/api/mcp` in the existing application and database. Six query tools cover context, accounts, instruments, Positions and Trades; `prepare_entry` and `commit_entry` provide the bounded entry workflow.
- Settings → MCP Credentials issues separate, named, revocable `read` and `entry` credentials. Secrets are shown once; only their digest and display prefix are stored. The default lifetime is 90 days. Server-side ownership and profile checks apply to every request.
- Entry supports a new Position plus first fills, single-/multi-leg additions to open Positions, and creation of missing instruments. Preparation saves only a draft, including contract specifications, defaults, fees, authoritative Decimal cash flow and time interpretation.
- Pending previews expire after 24 hours. After the user confirms, commit writes instruments, Position, all fills and the saved result in one transaction. Failed batches roll back; repeated/concurrent commits and retries after a lost response return the original result without duplicating records. Reuse the original `request_id` for preparation and `draft_id` for commit.
- `JOURNAL_TIMEZONE` explicitly sets the server entry timezone, defaulting to `UTC`. Per-leg IANA timezones and explicit offsets are supported; ambiguous/nonexistent daylight-saving times require an explicit offset. The database continues to store UTC and the website displays browser-local time.
- The same endpoint supports local loopback access and HTTPS reverse-proxy access. Configure the exact allowed Host and Origin values for remote access; preserve the MCP path, Bearer authorization and protocol headers.

## Compatibility and boundaries

The existing website's Position/first-Trade creation and failure recovery remain unchanged. MCP's atomic creation does not migrate that website flow. Trade archival, closed-position write locks, frozen P&L, append-only plans, numeric precision and separate currencies remain enforced.

This release adds no screenshot recognition, in-app model API/chat interface, broker import, close/reopen/archive/correction MCP tools or other management writes. SQLite is supported; PostgreSQL equivalence remains unverified.

## Upgrade notes

Take a consistent database backup and verify restoration separately before upgrading. The existing migrate-before-app Compose flow applies three new Alembic revisions, advancing `0003` to `0006`:

| Revision | Addition |
|---|---|
| `0004` | Dedicated MCP credential records |
| `0005` | Shared instrument-creation write coordination |
| `0006` | Immutable entry drafts and saved commit provenance/results |

No historical trading-data rewrite or timestamp backfill is included. Rollback of an upgraded deployment has not been validated; retain a compatible pre-upgrade backup and image rather than assuming an older image can use the upgraded schema.

The versioned image is `ghcr.io/t-liu93/trading-journal:1.2.0`; the tag workflow builds `linux/amd64` and `linux/arm64`, plus the `1.2`, `1` and `latest` aliases. Publication does not replace a running deployment. See [deployment](../../README.md#deployment) and [MCP setup/walkthrough](../walkthrough.md#mcp-client-setup-and-walkthrough) for configuration. Create new credentials on the intended service; the walkthrough credentials were revoked and its temporary database was removed.
