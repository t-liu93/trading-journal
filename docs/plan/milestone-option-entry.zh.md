## 1. 目标、基线与范围

### 1.1 目标

随着记录积累，过期期权和其他股票的期权不再挤占日常候选列表；用户选定 Primary Instrument 后，可以直接选择相关合约。同时修复成交变更后的开仓日期一致性，改善成交备注和录入表单的可读性。

典型结果：选择 AAPL 作为主标的 → 默认看到 AAPL 的未过期期权 → 创建缺少的合约时无需重选 underlying → 备注清楚对应成交 → 补录或归档后开仓日期同步更新。

- Instrument 已有期权到期日期和精确的 `underlying_id`。
- Instrument 列表支持类型、symbol 前缀和数量限制，默认最多返回 50 条，没有分页。
- First Trade、后续 Add Trade 没有传递 Primary Instrument 上下文。
- PMCC LEAP 选择器只限制品种为期权；后端校验 underlying 与 Position 主标的一致。
- Position 开仓日期创建后不随成交新增、归档维护；平仓日期会按有效成交推导。

## 2. 设计决策与公共契约

### D01 · 过期是查询条件

- `expiry < 当前 UTC 日期` 的期权视为已过期，到期当天仍展示，次日默认隐藏。
- 后端判定；这是日期级筛选，不代表交易所实时可交易状态。
- 不引入交易所日历、盘中截止时间或用户时区配置。
- 不新增归档状态，不删除合约，不修改关联交易。
- 后端提供可替换的当前 UTC 日期函数，测试固定日期。

### D02 · 默认隐藏与历史访问

- Instruments 页面、Primary Instrument、Trade Instrument 和 PMCC LEAP 选择器默认请求未过期合约。
- 页面或选择器附近提供 `Show expired options` 开关；开启后包含过期期权，其他筛选仍生效。
- 开关只在当前页面／表单会话内保留，不写数据库或 localStorage；重新打开交易表单恢复默认隐藏。
- 已选合约、历史 Position／Trade 和 PMCC 元数据仍通过按 ID 查询显示完整名称。
- 为回显加载的历史合约只用于当前值显示，不混入普通候选项。
- 关闭过期显示不清除已经明确选好的历史合约；清空后重新选择需要再次开启开关。

### D03 · 筛选在限制数量前执行

扩展 `GET /api/instruments`；响应继续为 `InstrumentRead[]`。

| 参数 | 类型／默认值 | 语义 |
|---|---|---|
| `kind` | 现有可选枚举 | 保留 |
| `q` | 现有可选字符串 | 保留 symbol 前缀搜索 |
| `limit` | 整数，默认 50，范围 1–200 | 保留 |
| `offset` | 整数，默认 0，最小 0 | 新增分页偏移 |
| `include_expired` | 布尔，默认 true | false 时排除过期期权 |
| `option_underlying_id` | 可选 UUID | 只限制期权行的 underlying，其他品种不受影响 |

- 为兼容旧客户端，API 缺省 `include_expired=true`；本产品各列表入口显式传 `false`。
- `kind=option` 与 `option_underlying_id` 组合只返回该 underlying 的期权。没有匹配 underlying 时返回空的期权结果；错误 UUID 格式返回 422。
- 先应用全部筛选，再排序、分页。排序保持 symbol、创建时间，并追加 ID 作为稳定排序条件。
- 保留按 ID 查询和 get-or-create 契约。不新增拒绝历史 Instrument／Trade 写入的后端规则。

最小分页：页面和选择器每页展示 50 条，请求 51 条，第 51 条只判断后续结果；下一页偏移增加 50。页面提供上一页／下一页，选择器提供加载更多。修改搜索、类型、过期或 underlying 条件后重置分页，追加页按 ID 去重。不新增总数或全量下载；并发新增合约不承诺跨请求快照一致性。

### D04 · 通过 underlying ID 关联

- 股票 Primary Instrument 使用其 ID；期权 Primary Instrument 使用其 `option.underlying_id`。
- 外汇或尚未选择主标的时不施加期权 underlying 条件。
- 股票和外汇候选保持现有品种行为，不把通用成交表单改成只能录入期权。
- PMCC LEAP 只允许期权，沿用后端“underlying 等于 Position 主股票 ID”的校验。对不满足现有主标的条件的记录，Meta 表单明确提示，不放宽后端校验。
- 主标的解析失败时显示错误与重试；需要关联筛选的入口暂停选择，不能静默退回全量期权。
- 比较解析后的 underlying ID，同一 underlying 不清空期权选择；underlying 改变或主标的被清空时，清除不再匹配的期权选择并提示。
- 保留数量、价格、日期、费用和备注，仅按既有品种规则清除不适用的 Action。非期权腿不因本次期权筛选被清除。

### D05 · 内嵌创建继承上下文

- 有明确 underlying 时提供“为当前标的新建期权”的入口，不依赖搜索结果为空。
- 自动带入 underlying、币种、交易所；当前上下文中的 underlying 不可改。
- 到期日、Call／Put、行权价、数量、价格和交易方向仍由用户选择或填写。
- Instruments 管理页的通用创建保留手动选择 underlying。
- 明确创建过期合约时，自动开启当前选择器的过期显示并提示，再选中返回的合约。
- 返回合约必须符合当前 underlying 上下文，不匹配时不能自动选中。
- 保留 get-or-create 去重和失败恢复。

### D06 · 请求竞态与错误处理

- 搜索词、类型、underlying、过期状态、分页构成完整请求上下文。
- 条件变化时立即使旧请求失效，包括尚未发出的防抖请求。迟到响应不能恢复旧候选或加载状态。
- 条件变化移除旧候选，当前选中值的回显单独保留。
- 请求失败显示错误与重试，不伪装成空结果。加载更多失败保留有效页，重试同一偏移。
- 卸载时清理定时器，使未完成请求不能写回状态。
- 每次打开选择器重新查询；不要求午夜自动清除正在编辑的选择。

### D07 · 开仓日期取有效成交最早时间

- 未平仓 Position 成功新增或归档 Trade 后，取非归档成交的 MIN(`executed_at`)。
- 首笔有效成交可以将创建日期向前或向后替换。
- 全部归档后保留上次开仓时间；下一笔成交重新建立日期。新建空 Position 在首笔成交前保留传入时间。
- 成交变更与日期维护同事务提交，批量失败不得留下部分成交或日期修改。Notes-only PATCH 不触发维护。
- 新成交先按 UTC 归一化，再持久化、排序；覆盖不同 offset 的同一时间。
- 沿用当前 SQLite 日期存储约定，无时区输入按 UTC 解释。不推测、回填旧记录已丢失的时区信息，不做全库时间重构。

### D08 · 平仓顺序与历史边界

- open→closed 时，有有效成交则先重算开仓时间。
- 无显式平仓时间时取有效成交最大时间；空集取当前 UTC 时间。
- 允许 `closed_at == opened_at`；`closed_at < opened_at` 返回 422，状态、日期、其他 PATCH 字段和冻结盈亏均不得部分保存。
- 已平仓记录显式修改 `closed_at` 时做相同顺序校验，不重算开仓日期或冻结盈亏。
- 读取或修改其他允许字段不自动修复或拦截旧的异常日期记录。
- 保留归档、closed Trade 写锁、禁止重新开仓、Decimal 计算和只追加计划。
- 不通过隐藏负持仓天数掩盖后端错误。

### D09 · 备注与表单布局

备注：每笔成交有备注或正在编辑时，在其数据行后增加紧邻的备注行，跨全部表格列，以 Trade ID 关联。移除分组底部重复备注；普通文本显示，保留换行、自动折行，不渲染 HTML。`Edit notes` 仍在对应操作区，编辑器在备注行；Enter 换行，Ctrl／Command＋Enter 保存，并提供保存／取消按钮。保存失败保留输入，只读切换取消编辑，归档和已平仓限制不变。

表单：共用成交腿字段上置标签，下方放帮助和错误信息。600px 以下单列，较宽时双列，Instrument 和 Notes 使用整行。验证失败定位具体腿和字段，保留输入与增删腿。帮助使用产品语言，不暴露字段名、数据库或服务端实现细节。本轮只改善涉及组件的窄屏布局，不声明全站移动端适配。

### D10 · 测试与数据演进

- 前端使用 Vitest、Vue Test Utils v2、jsdom，分别提供测试运行、Vue 3 组件交互和 DOM 环境。依据：[Vitest](https://vitest.dev/guide/)、[Vue Test Utils](https://test-utils.vuejs.org/guide/)。
- 使用独立测试配置，避免改写自动生成的组件声明。依赖锁定到与当前 Node 22／Vite 8 兼容的版本，不顺带升级现有工具链；保留 `.npmrc`。
- `npm run test` 执行一次性测试，另提供 watch 脚本。不引入 Playwright 或覆盖率数字门槛。
- 不需要数据库迁移；OpenAPI 参数变化后重新生成 `schema.d.ts`，不得手改。
- 所有验证使用合成数据和隔离数据库，不读取或修改生产数据库。
