# 任务卡模板

> [English](task-template.md) · **中文**

独立任务或里程碑内的原子章节都用此契约，进入 ready 前替换占位内容。[路线图](roadmap.zh.md) 管理调度，本卡管理详细范围和验收。提议任务卡不等于实现授权。

## 身份与前提

- ID／标题：
- 队列状态：链接路线图对应行。
- 设计：草案／已确认，记录实际确认。
- 依赖：
- 目标：用户可见问题与目标行为。
- 当前证据：相关源码、测试和原始问题，区分检查事实与假设。

## 范围与契约

- 输入、输出和 API／数据／UI 行为，兼容性与失败行为。
- 范围内：
- 范围外：
- 文件：准确路径及新建／修改／删除动作，包含必要回归测试。实质范围变更上报，常规实现选择自主决定。
- 迁移／数据：目标、默认、回滚／对账和一次性验证数据；不需要时也明确说明。
- 实施步骤：有顺序、可独立检查，必要时同一结果包含前后端集成。

## 验收与评审清单

- [ ] 具体可观察结果：
- [ ] 负向／边界：
- [ ] 相关检查与预期：
- [ ] 无无关行为、归属或历史回归：
- [ ] 必要生成类型／文档同步：

评审重点是本任务实际的正确性、安全、数据和兼容风险。说明什么构成阻塞问题，可选改进单列。指定独立检查，不让 reviewer 依赖实施报告的结论。

## 候选与证据

- 候选：base/head SHA，或包含相关未跟踪文件的可复现 diff／快照。
- 实现：未开始／完成／部分完成，说明范围。
- 自动检查：未运行／通过／失败，写实际命令和遗漏。
- 独立评审：未要求／待进行／通过／有问题，注明候选版本。
- 用户验收：待验收／接受／明确跳过部分后接受，记录实际确认与未测路径。
- 本地证据：运行目录／报告标识；理解契约不应依赖稳定指导链接到被忽略文件。

详细日志和报告放在被忽略的 `development-notes/<run-id>/`，本卡只保留简洁结果。评审通过只覆盖记录的候选，后续修改需验证变化范围。

## 手动走查与清理

记录一次性环境、合成输入、准确启动／操作、预期观察及只清理本任务资源的方式。说明前提，跳过检查必须有明确例外记录。不对生产环境执行。

## 决策与完成

记录实质决策、未决问题和明确例外。实现／检查／评审／人工验收变化后同步路线图，不因一次构建成功就把四项都标完成。执行／授权遵循[开发指南](../development.zh.md)和被调用技能，不在此复制规则。
