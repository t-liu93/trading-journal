## 1. 目标、基线与范围

### 1.1 目标

在 Codex 或 Hermes 中用自然语言创建 Position 或增加 Trade：Agent 查询上下文、追问缺项、展示服务端预览，用户在对话中确认后提交。

本里程碑不在 Trading Journal 内调用模型。外部 Agent 理解自然语言，后端提供确定性的查询、校验、计算和写入能力。

典型流程：描述交易 → 查询账户／仓位／品种 → 补齐缺项 → 准备预览草稿 → 对话确认 → 提交草稿 → 返回记录 ID 和网站链接。

### 1.2 当前事实

- 已有 Account、Instrument、Position 和 Trade API；浏览器鉴权使用 Cookie 与数据库 session。
- 尚无独立 Agent 凭证、MCP 服务或录入草稿。
- 多腿 Trade 已支持原子写入；Position＋首批 Trade 当前仍是两次前端请求，依靠部分失败恢复。
- Instrument get-or-create 主要仍在 API 路由中，需要提取复用。
- 已有后端 Decimal 计算、有效成交日期维护、归档排除和已平仓成交写锁。
- 时间按 UTC 存储、浏览器本地时间显示；没有独立的服务器默认录入时区设置。
- Codex 与 Nous Research Hermes 支持 HTTP MCP，可共用服务并分别配置凭证。依据：[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)、[Hermes MCP](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)。实际安装的客户端仍需集成检查。

## 2. 共享决策与公共契约

### D01 · Agent 解释自然语言

MCP 接受结构化字段，不接受一段文字后由 Trading Journal 发给模型。Agent 负责理解表达、查询候选、追问和展示预览；服务端负责校验、计算、权限及事务。

账户／仓位／合约有多个匹配时请用户选择，不按相似名称猜测。期权不能仅由买卖静默推断 BTO／STO／BTC／STC；缺少合约身份或开平仓意图时必须澄清。

### D02 · 工具边界

| 工具 | 输入／输出契约 |
|---|---|
| `get_context` | 当前 UTC 时间、服务器默认时区及当地时间、支持的策略和成交方向 |
| `list_accounts` | 所属账户；默认排除已归档账户 |
| `search_instruments` | 类型、symbol、币种、交易所及期权 underlying／到期日／行权价／Call-Put 筛选，返回完整规格 |
| `list_positions` | 账户、主标的、策略和状态筛选 |
| `get_position` | 所属 Position 详情、主标的和现金流；不嵌入无限成交列表 |
| `list_trades` | 所属仓位成交；默认排除已归档成交 |
| `prepare_entry` | 校验新仓位＋首批成交或已有仓位追加成交，保存预览草稿 |
| `commit_entry` | 仅按草稿 ID 提交，不接受替换交易字段 |

列表工具使用 `limit`／`offset`，默认 50 条、最多 200 条、偏移非负，返回 `items`／`has_more`。全部筛选先于分页，排序包含稳定 ID。历史／归档访问通过显式筛选，保留所有权检查。MCP 品种搜索默认包含过期合约，方便补录；不改变现有网站选择器默认值。

### D03 · 结构化录入输入

`prepare_entry` 接受调用方生成的 UUID `request_id`、`kind`（`open_position` 或 `add_trades`）及非空成交数组。新仓位提供账户、Primary Instrument、策略及可选财务值／备注；追加提供 `position_id`，两种分支互斥。

每腿包含品种、方向、数量、价格、执行时间、可选时区、commission／fees 和备注。品种引用必须二选一：已有 `instrument_id`，或沿用当前股票／期权／外汇字段的待创建 `InstrumentCreate` 描述。相同待创建描述在提交时按自然键复用同一品种。订单分组遵循已有多腿语义。

使用 Decimal 和现有持久化精度；金额输出为十进制字符串。不接受调用方控制的 `user_id`、成交所属账户或权威现金流。缺项／无效字段返回带字段路径的问题，不产生有效草稿。不能猜测账户、合约、成交时间、数量、价格或方向。

沿用现有可选项：资金／风险／收益可以为空；省略 commission／fees 时采用现有零值默认，必须显示。新合约默认值（包括 multiplier／style）必须出现在预览中。不新增策略参数、价格或交易意图推断。

### D04 · 录入时间口径

增加运维环境设置 `JOURNAL_TIMEZONE`：IANA 时区、默认 `UTC`；无效配置启动失败。运行依赖包含时区数据，不依赖宿主机与容器系统时区一致。

- 无时区偏移的执行时间使用明确提供的 IANA 时区，否则采用 `JOURNAL_TIMEZONE`。
- 带偏移时间以该偏移为准；同时给 IANA 时区时，必须与该当地时间一致。
- 夏令时造成不存在／重复的当地时间时拒绝，要求明确偏移。
- Agent 获取 `get_context` 后将“今天”转成具体日期，服务端不保存相对日期表达式。
- 草稿冻结具体 UTC 时刻，后续配置变化不重新解释。
- 预览输入时区、服务器默认时区表示及 UTC。继续按现有约定存 UTC，不改变既有 REST 无时区输入按 UTC 解释或浏览器显示行为。

### D05 · 不可变预览草稿

草稿绑定用户、创建凭证和 `request_id`，待提交草稿 24 小时过期。同一凭证／请求 ID 和相同原请求返回同一草稿，不延长有效期；相同 ID 不同内容返回冲突，变更使用新请求／草稿。重放先检查原请求身份，再应用当前默认值，避免重试重新解释已有草稿。

保存原请求摘要、规范化输入、预览、默认值、来源身份、有效期及提交结果。状态为 `pending`／`committed`，待提交是否过期由截止时间判断。准备阶段只写草稿，不创建真实品种、仓位或成交。不因不同请求描述相似成交而自动去重。

预览包含账户、目标／新仓位、完整品种、每腿方向／数量／价格／费用／时间、计算现金流、待创建品种及默认值。复用后端计算与持久化精度。解析到已有品种但规格冲突时返回字段冲突，不静默改变请求的合约。

### D06 · 原子、幂等提交

重新校验凭证、有效用户、所有权、草稿期限和目标当前状态。新仓位账户须满足既有可用性规则；追加沿用当前 Trade／账户契约。不放宽或顺带扩展领域规则。

品种创建／复用、可选 Position 创建、全部 Trade、开仓日期维护和草稿结果必须同事务完成。失败全部回滚，包括新 underlying／期权、空仓位、部分成交及草稿消费。

同一草稿并发／重复提交只产生一组记录，返回保存结果。瞬态 SQLite 竞争返回可重试错误，仍重试原草稿。已提交结果不受待提交期限限制，但仍要求原有效凭证和用户。保存凭证 ID、提交时间、生成 ID 及网站相对链接，不保存凭证明文。

品种沿用当前自然键。网站与 MCP 品种创建使用同一数据库级写入协调，在自然键复查前获得写锁，不使用进程内锁。在 `app_config` 中使用固定协调行。已有多条匹配／规格冲突明确报错，不自动整理历史。本轮不新增品种唯一约束或修复已有品种。

### D07 · 确认与权限

Agent 必须展示每批预览并在对话中获得确认后提交。初始化说明及工具描述明确该流程。不可变草稿绑定预览与提交内容；服务端不能独立证明其他 Agent 的聊天中发生过用户确认。不新增网站确认步骤。

凭证档位：`read` 提供上下文／查询，`entry` 增加准备／提交。即使手工调用写工具，处理器仍须拒绝 `read` 凭证，不依赖工具是否可见。不暴露任意 SQL、HTTP 或通用 REST 代理工具。

### D08 · 凭证生命周期

增加 Cookie 登录保护的管理端点 `GET /api/mcp-tokens`、`POST /api/mcp-tokens`、`DELETE /api/mcp-tokens/{id}`。具名凭证归属用户、可撤销，默认 90 天到期；创建时可显式选择其他未来期限或无期限。

生成高熵随机凭证，只存摘要和展示前缀。原文仅创建时返回一次，不出现在后续列表、日志或审计记录中。DELETE 标记撤销，保留草稿来源关联。撤销、到期或用户禁用对后续请求生效；他人凭证返回 404。

Codex／Hermes 分别配置凭证。MCP 凭证不是浏览器 session，不授予通用 REST 写入或凭证管理权限。前端只在当前揭示状态保留明文，关闭／离开页面时清除，不写 localStorage。

### D09 · 传输与部署

使用官方 Python MCP SDK，以 Streamable HTTP 在现有 FastAPI 容器／数据库挂载精确 `/api/mcp`。依据：[MCP 传输](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)、[Python SDK](https://github.com/modelcontextprotocol/python-sdk)。锁定兼容当前 Python／FastAPI 的版本，不顺带升级工具链。

手动配置的 Bearer 鉴权覆盖初始化、发现、调用及其他 MCP HTTP 请求，工具同时校验权限。不构造或声明虚假的 OAuth 发现／登录流程。传输运行不依赖进程内录入状态，草稿重启后保留。

本机保留 loopback 端口映射，远程通过 HTTPS 反代访问同一入口。增加 MCP 专用允许 Host／Origin 配置，默认本机地址；正常无 Origin 的 Agent 请求可通过，明确不允许的 Origin 被拒绝。协议错误不能落入 SPA、登录 HTML 或路径重定向。

### D10 · 兼容性与数据边界

保留服务端所有权、跨用户 404、归档排除、closed Trade 写锁、冻结盈亏、只追加计划、数字精度和币种分离。新增 Position＋首批 Trade 原子录入仅供 MCP，现有网站两请求创建／恢复流程不在本轮迁移。

提取服务后，既有成功 REST 请求、响应、状态码和业务行为保持兼容。Schema 增加使用新 Alembic migration，不改已发布迁移、回填历史或纠正真实数据。下列拟新增应用文件目前不存在。实现检查只使用一次性数据库及合成数据。

### 4.2 用户走查

使用新建临时数据库、Compose 项目、镜像、端口和 Agent 配置，不替换既有 Agent 配置。

1. 在网站签发分别给 Codex／Hermes 的录入凭证和一个只读凭证。
2. Codex 准备新仓位和首批成交；确认只有预览时不产生业务记录，再确认并检查网站。
3. Hermes 查询该仓位并追加成交；补录更早时间并检查开仓日期。
